# Расшифровка записей встреч

Инструмент делает из видео- или аудиозаписи любой встречи (совещание, созвон, интервью, вебинар, лекция) два документа. Можно и без записи: расшифровывать созвон на лету, прямо во время встречи (см. «На лету, во время встречи»).

- **полный текст**, разбитый на абзацы. Каждый абзац начинается с таймкода `[чч:мм:сс]`, поэтому любое место легко найти в записи и переслушать. По желанию текст делится по говорящим («Говорящий 1», «Говорящий 2»), а ИИ может проверить его: подставить имена и исправить реплики, отданные не тому человеку;
- **выжимку** (по желанию): все главные идеи, решения, задачи с ответственными и сроками, **все названные даты**, открытые вопросы и темы по времени. Везде стоят таймкоды, воды нет.

Расшифровка идёт **локально на вашем компьютере**: запись никуда не отправляется. Наружу уходит только текст расшифровки, и только если вы сами попросили проверку или выжимку и выбрали для них облачный ИИ (подробнее в разделе «Выжимка и правила использования ИИ»).

Скорость: 3 часа записи обрабатываются примерно за 10 минут на видеокарте NVIDIA. На компьютере без NVIDIA работа идёт на процессоре и занимает в несколько раз дольше, но тоже работает.

## Аккаунты

Инструмент не привязан ни к чьему аккаунту:

- для расшифровки аккаунт не нужен вообще. Модель Whisper скачивается при установке с Hugging Face без входа;
- проверку текста и выжимку делает ИИ, установленный **у вас**, под **вашим** аккаунтом: Claude Code, ChatGPT (через Codex CLI) или локальная модель (Ollama, LM Studio и др.). Инструмент запускает его без ваших личных настроек и не сохраняет сессию в истории.

## Что нужно

- Windows 10 или 11, или Linux (см. раздел «Linux»);
- около 4 ГБ свободного места и интернет на время установки;
- `git`, чтобы скачать инструмент и потом обновлять его;
- `winget` (есть в Windows 10 и 11 по умолчанию): через него `windows\setup.cmd` сам поставит `uv`, менеджер Python, если его ещё нет;
- только для выжимки, одно из:
  - Claude Code, в котором вы вошли в свой аккаунт (проверка: `claude --version`);
  - Codex CLI от OpenAI, в котором вы вошли под ChatGPT-аккаунтом (проверка: `codex login status`);
  - запущенная локальная модель: Ollama, LM Studio или другой сервер с интерфейсом в стиле OpenAI.

## Установка

1. Если `git` ещё не установлен, установите его в PowerShell и откройте новое окно терминала:
   ```
   winget install --id Git.Git
   ```
2. Скачайте инструмент в папку, например в `C:\bin\transcribe`:
   ```
   git clone https://github.com/sbaranau/transcribe.git C:\bin\transcribe
   ```
   Путь может быть любым, но после установки папку не перемещайте (см. «Если что-то не работает»).
3. Запустите `windows\setup.cmd` из папки инструмента двойным щелчком или из терминала. Если `uv` нет, он сначала поставит его через `winget`; при первом использовании `winget` может попросить вас принять его соглашения. Затем он скачает в папку `app\`:
   - собственный Python 3.12;
   - пакеты вместе с библиотеками NVIDIA, около 1,5 ГБ;
   - модель Whisper `large-v3-turbo`, около 1,6 ГБ;
   - модели для разделения по голосам, около 45 МБ.

   В самом начале он спросит, добавить ли инструмент в меню «Отправить» (см. «Через меню „Отправить“»). Ответ `Y` или `N`; передумать можно потом в любой момент.

   Занимает 5–15 минут. В конце в папке инструмента появятся три ярлыка со своими значками, ими и пользуйтесь:
   - **«Расшифровать запись»** (синий лист с волной звука): готовая запись, перетаскиванием;
   - **«Расшифровка встречи на лету»** (красный микрофон): созвон прямо во время встречи;
   - **«Установка и обновление»** (серая шестерёнка): запускает установку ещё раз.

   Последняя строка установки: `Setup complete.` Ярлыки можно скопировать на рабочий стол или закрепить на панели задач.

Системный Python и другие программы установка не трогает: всё лежит внутри папки инструмента.

### Язык интерфейса

Окно, вопросы в консоли и названия ярлыков бывают на русском, английском и немецком. Язык выбирается так:

- в окне расшифровки на лету: список «Язык интерфейса» справа вверху (до начала записи). Окно сразу перестраивается на новом языке, модель заново не загружается;
- из терминала: `windows\transcribe.cmd --ui-language de` (или `en`, `ru`) вместе с остальными параметрами.

Выбор запоминается в `app\ui.local.ini`. Ярлыки, пункт в меню «Отправить» и пункты меню Linux при этом переименовываются; второго набора не остаётся. Без выбора берётся язык ярлыков, которые уже есть в папке: у установок до 13.11.2026 это русский, даже если Windows на английском. Если ярлыков ещё нет, берётся язык системы, а если он не из этих трёх, английский.

Язык интерфейса не влияет на сам текст: расшифровка, метки говорящих («Вы», «Говорящий 2») и выжимка всегда на языке встречи. Служебные сообщения о ходе работы (`Model loaded`, `Transcript done` и т.п.) на английском.

### Обновление

```
git -C C:\bin\transcribe pull
```

Если в обновлении поменялись пакеты или модели, после этого запустите ярлык «Установка и обновление» (`windows\setup.cmd`). Уже скачанные модели повторно не скачиваются. Ваш словарь `terms.txt` при обновлении не трогается.

**Обновление с версии, где файлы `.cmd` лежали прямо в папке инструмента** (до 12.11.2026): теперь они в папке `windows\`, а для запуска есть ярлыки со значками. После `git pull` один раз запустите `windows\setup.cmd`: он создаст ярлыки и, если ответить `Y`, заново сделает пункт в меню «Отправить» (старый указывает на файл, которого больше нет). Если `python\`, `venv\` и `models\` ещё лежат прямо в папке инструмента, он перенесёт модели в `app\models`, ничего не скачивая заново, а `python\` и `venv\` создаст заново в `app\`.

## Как пользоваться

### Готовая запись: перетаскиванием (проще всего)

Перетащите один или несколько файлов записи в Проводнике на ярлык **«Расшифровать запись»**. Можно и наоборот: откройте ярлык двойным щелчком и перетащите файл в открывшееся окно, затем нажмите Enter.

Дальше в окне появятся вопросы. На каждый отвечайте цифрой и Enter. Просто Enter означает вариант «не знаю» или «нет»:

| Вопрос | Варианты | Просто Enter |
|---|---|---|
| Язык записи | 1 русский, 2 английский, 3 немецкий, 4 французский, 5 несколько языков | определить автоматически |
| Разделить текст по говорящим? | 1 да, 2 нет | нет |
| Сколько человек говорит? (только если ответили «да») | число от 1 до 20 | определить автоматически |
| Проверить текст с помощью ИИ? (только если текст делится по говорящим) | 1 да, 2 нет | нет |
| Сделать выжимку с помощью ИИ? | 1 да, 2 нет | нет |
| Какой ИИ использовать? (если на проверку или выжимку ответили «да») | только те ИИ, что найдены у вас: Claude, ChatGPT (Codex), локальная модель | первый в списке |

Текст и субтитры получаются всегда. Готовые файлы появляются в подпапке с именем записи рядом с ней (см. «Что получается»). Окно закроется после нажатия любой клавиши.

**Советы к вопросам:**
- **Язык.** Если знаете язык, укажите его: автоматика смотрит только первые 30 секунд. «Несколько языков» нужен, когда на встрече действительно переходят с языка на язык. Тогда язык определяется заново для каждого 30-секундного куска, а это чуть медленнее и иногда ошибается на коротких фразах.
- **Число говорящих.** Если знаете его, обязательно укажите: так разделение заметно точнее. Автоматический подсчёт ошибается чаще, особенно когда кто-то говорит совсем мало.
- **Какой ИИ.** Claude и ChatGPT получают текст расшифровки по интернету под вашим аккаунтом. Локальная модель работает на вашем компьютере, и текст никуда не уходит, но выжимка обычно получается слабее и делается дольше.
- **В списке только ИИ, готовые к работе:** установленные и с выполненным входом (у локальной модели — запущенный сервер). Рядом с Claude показан аккаунт, под которым выполнен вход, чтобы не перепутать рабочий и личный. Если ИИ установлен, но вход не выполнен, инструмент так и скажет и подскажет, как войти (`claude`, затем `/login`; или `codex login`).

**Если ни один ИИ не найден,** инструмент так и скажет и предложит:
- `1` — отменить проверку и выжимку (текст и субтитры всё равно сохранятся);
- `2` — указать путь к установленному ИИ: к `claude.exe` или `codex.cmd` (можно к папке, где он лежит), или адрес локального сервера, например `http://127.0.0.1:11434`.

Верный путь запоминается в файле `app\ai.local.ini`, и в следующий раз ИИ найдётся сам. Чтобы снова искать автоматически, удалите этот файл.

### На лету, во время встречи

Откройте ярлык **«Расшифровка встречи на лету»** перед созвоном или в его начале. Откроется окно «Расшифровка встречи». Видео не пишется: инструмент слушает звук компьютера (то, что говорят собеседники в Teams, Zoom и т.п.) и ваш микрофон.

1. **Перед началом.** Пока грузится модель (несколько секунд, справа вверху написано «Загружаю модель…»), выберите:
   - язык встречи («Определить автоматически» — по первым фразам);
   - «Переводить на»: без перевода или на английский, немецкий, русский (см. «Перевод»). Тогда справа от текста появится вторая колонка с переводом;
   - микрофон, обычно уже выбран тот, что по умолчанию;
   - звук компьютера: отмечены **все** устройства вывода (динамики, гарнитура, монитор), так собеседники будут слышны, куда бы ни шёл звук созвона.

   Нажмите **«Начать запись»**. Результат пишется в `Документы\Transcripts\<дата время>\`.
2. **Во время встречи** в окне видно:
   - красный индикатор «Идёт запись» и время;
   - уровни звука «Микрофон» и «Звук компьютера». Так видно, что обе стороны слышны; если какой-то звук долго молчит, рядом появится «тишина»;
   - **жёлтая полоса**, если собеседников слышно, а ваш микрофон молчит больше 20 секунд: проверьте, не выключен ли он кнопкой на гарнитуре или в программе созвона и тот ли микрофон выбран;
   - текст с таймкодами и метками: **«Вы:»** (синим) и **«Собеседник 1:»**, **«Собеседник 2:»**… (у каждого свой цвет). Собеседники различаются по голосу прямо во время звонка. Если вы пишете только микрофон (встреча в комнате), метки будут «Говорящий 1», «Говорящий 2»… Текущая, ещё не законченная фраза каждой стороны показывается серым курсивом через 2–3 секунды после сказанного, а затем заменяется окончательным вариантом. Окно само прокручивается к концу; если вы отмотали назад перечитать, прокрутка ждёт, пока вы не нажмёте «↓ К концу»;
   - кнопки «Открыть папку», «Копировать текст», «A− / A+» (размер текста).

   Текст сразу записывается в `meeting.live.txt`, звук — в `meeting.wav` в два канала: микрофон слева, звук компьютера справа (около 200 МБ на 3 часа). Если записывается только микрофон, канал один.
3. **Остановить.** Последние фразы допишутся. Если закрыть окно крестиком, инструмент спросит, остановить ли запись; текст и звук при этом тоже сохранятся.
4. **«Что дальше».** После остановки в том же окне можно отметить:
   - «Расшифровать запись заново целиком» (качество лучше, чем на лету; отмечено по умолчанию);
   - «Разделить собеседников по голосам» и сколько всего человек, **вместе с вами** (0 — не знаю). Ваши реплики при этом остаются «Вы»: инструмент знает их по каналу микрофона и по голосам разделяет только собеседников («Собеседник 1», «Собеседник 2»…). Даже без этой галочки текст делится на «Вы» и «Собеседники»;
   - «Проверить текст с помощью ИИ»;
   - «Перевести текст на» и язык: локальный перевод полного текста (если переводили на лету, этот язык уже выбран);
   - «Проверить перевод с помощью ИИ» (только вместе с переводом);
   - «Сделать выжимку с помощью ИИ»;
   - какой ИИ использовать: в списке только установленные и с выполненным входом, рядом с Claude виден аккаунт. Если готовых нет, под списком сказано, что сделать, и есть поле для пути к `claude.exe` / `codex.cmd` или адреса локального сервера;
   - «Удалить звук встречи после обработки».

   Нажмите **«Выполнить»**. Пока идёт обработка, галочки и выбор ИИ заблокированы, а вместо «Выполнить» стоит **«Остановить обработку»**: она прерывает работу (вместе с запущенным ИИ). Уже готовые файлы остаются, незаконченный текст удаляется, звук не удаляется; «Выполнить» запускает обработку заново. Ход работы виден внизу окна, в конце появятся кнопки «Открыть: Текст», «Открыть: Выжимку» и т.д. Кнопка «Закрыть» внизу справа; если закрыть окно во время обработки, инструмент спросит, остановить ли её. Результат: `meeting.txt`, `meeting.checked.txt`, `meeting.en.txt` (перевод), `meeting.en.checked.txt`, `meeting.summary.md` в той же папке.

**Что важно знать:**
- **Предупредите участников, что встреча расшифровывается.** Для встреч с клиентами, скорее всего, нужно их согласие.
- **Ваш голос и собеседники распознаются отдельно.** Поэтому ваши реплики не путаются с чужими. **Собеседники различаются по голосу на лету:** каждая их фраза сравнивается с уже услышанными голосами. Это предварительная разметка: на тестовых совещаниях на 4 человека найдено от 3 до 5 голосов, правильному человеку приписано 73–93 % времени речи. Точнее разделяет полная обработка после остановки («Разделить по говорящим»), потому что она слышит всю запись сразу. Если в начале звонка кто-то говорил лишь пару слов, его фразы могут сначала попасть к другому собеседнику.
- **Микрофон усиливается автоматически.** Teams и другие программы созвонов во время звонка часто убавляют системный уровень микрофона (свой поток они потом усиливают сами), и другие программы слышат вас еле-еле. Инструмент подтягивает уровень вашего голоса, поэтому тихий микрофон не теряется на фоне собеседников.
- Чистовой текст на лету появляется кусками по 20–30 секунд: так модель слышит фразу целиком и почти не уступает полной расшифровке (на тестах совпадение 91–93 % слов). Пока кусок не закончен, в окне виден черновик. Он появляется через 2–3 секунды, но в нём больше ошибок, и потом его заменяет чистовой текст.
- Нужна видеокарта NVIDIA. На процессоре текст может заметно отставать от разговора.
- Если вы говорите через динамики, а не через гарнитуру, микрофон слышит и собеседников. Такие слова инструмент находит (они совпадают с тем, что в это же время играл компьютер) и убирает из ваших реплик, чтобы они не дублировались. С гарнитурой всё равно чище.
- Вместе с окном расшифровки запускается чёрное окно консоли, свёрнутое на панель задач. Не закрывайте его: это сам инструмент, в нём видны только служебные сообщения.
- Без окна, прямо в консоли (остановка по Enter): `windows\transcribe.cmd --live --console --ask`.

### Через меню «Отправить» (по желанию)

Если при установке вы ответили `Y`, папку инструмента держать открытой не нужно: правый щелчок по записи → «Отправить» → «Расшифровать» (с тем же синим значком). Это то же, что ярлык «Расшифровать запись», с теми же вопросами. В Windows 11 пункт «Отправить» находится в «Показать дополнительные параметры» (или Shift + правый щелчок).

Включить или убрать меню позже: запустите `windows\send-to-menu.cmd` и выберите `A` (добавить) или `R` (убрать). Он меняет только ярлык инструмента в вашей папке «Отправить», больше ничего.

### Из терминала (если нужны параметры)

Обычно хватает ярлыка «Расшифровать запись». Из терминала удобно, если нужны параметры, которых нет в вопросах, или обработка многих файлов без вопросов:

```
C:\bin\transcribe\windows\transcribe.cmd "D:\Записи\встреча.mp4" --language ru
C:\bin\transcribe\windows\transcribe.cmd "D:\Записи\встреча.mp4" --language ru --speakers 3 --check --summary --srt
C:\bin\transcribe\windows\transcribe.cmd "D:\Записи\встреча.mp4" --ask
C:\bin\transcribe\windows\transcribe.cmd "D:\Записи\встреча.txt" --check --summary
```

`--ask` задаёт те же вопросы, что и перетаскивание. Последняя команда проверяет готовый текст и делает по нему выжимку, без повторной расшифровки.

Параметры:

| Параметр | Что делает |
|---|---|
| `--language ru` | язык встречи: `ru`, `de`, `en` и т.д., или `multi`, если говорят на нескольких языках. Без него язык определяется по первым 30 секундам |
| `--speakers` | разделить текст по говорящим; `--speakers 3`, если известно, что говорят трое |
| `--ask` | задать вопросы о языке, говорящих, проверке и выжимке (о том, что не указано параметрами) |
| `--check` | проверить текст с помощью ИИ: имена вместо номеров и исправление реплик с чужой меткой (см. «Проверка текста ИИ») |
| `--summary` | сделать выжимку с помощью ИИ |
| `--ai claude` | каким ИИ проверять и делать выжимку: `claude`, `codex` (ChatGPT) или `local` (локальная модель). Без него берётся первый найденный |
| `--srt` | записать субтитры с точными таймингами |
| `--out-dir ПАПКА` | куда класть результаты (по умолчанию подпапка с именем записи рядом с ней) |
| `--cpu` | работать на процессоре, даже если есть видеокарта |
| `--terms ФАЙЛ` | дополнительный словарь терминов для этой встречи (см. «Словарь терминов») |
| `--no-terms` | расшифровать без словарей |
| `--no-filter` | не убирать «галлюцинации» Whisper (см. ниже), оставить всё как есть |
| `--translate en` | перевести текст локально на `en`, `de` или `ru` (см. «Перевод») |
| `--check-translation` | вместе с `--translate`: проверить перевод с помощью ИИ |
| `--force` | перезаписать уже готовые результаты (см. «Повторный запуск») |
| `--ui-language de` | язык вопросов, окна и ярлыков: `en`, `de` или `ru`; запоминается (см. «Язык интерфейса») |

Подходят все обычные форматы: mp4, mkv, mov, webm, mp3, m4a, wav и другие.

## Что получается

Для каждой записи рядом с ней создаётся подпапка с тем же именем, и все результаты лежат в ней:

```
D:\Записи\встреча.mp4
D:\Записи\встреча\встреча.txt
D:\Записи\встреча\встреча.srt
D:\Записи\встреча\встреча.checked.txt
D:\Записи\встреча\встреча.summary.md
```

Если делать выжимку по готовому `.txt`, она появится рядом с этим `.txt`.

- **`<имя>.txt`**: полный текст. Новый абзац начинается примерно каждые 30 секунд речи (по концу предложения), после паузы или, если включено разделение по говорящим, при смене говорящего. Имена, фамилии и технические термины распознаются с ошибками чаще обычных слов.
- **`<имя>.srt`**: субтитры, чтобы пересмотреть спорный кусок с текстом поверх видео. При разделении по говорящим у каждого субтитра стоит метка говорящего. Автоматически плеер берёт субтитры только из папки с видео, поэтому подключите их вручную (в VLC: «Субтитры» → «Добавить файл субтитров») или переложите `.srt` к видео.
- **`<имя>.checked.txt`** (если выбрана проверка): тот же текст с именами вместо номеров и исправленными метками, см. «Проверка текста ИИ».
- **`<имя>.summary.md`**: выжимка, целиком на языке встречи. Если была проверка, выжимка делается по проверенному тексту. Для русской встречи разделы такие:
  - «Коротко»: 3–5 предложений;
  - «Главные идеи»: каждая идея, предложение, довод и цифра отдельным пунктом, сгруппированы по темам;
  - «Решения»;
  - «Задачи»: таблица Что | Кто | Срок | Таймкод;
  - «Даты и сроки»: таблица со **всеми** названными датами, днями недели, временем и сроками, в том числе относительными («завтра», «через две недели»). Они записываются так, как прозвучали: дата записи неизвестна, и пересчитывать их ИИ не будет. Если дат не было, так и написано;
  - «Открытые вопросы»: нерешённое, отложенное, риски;
  - «Темы по времени»: по строке на тему с диапазоном таймкодов, чтобы найти место в записи.

  Пустые разделы пропускаются, кроме дат. ИИ велено не пропускать ни одной идеи, но обходиться без вступлений, повторов и общих слов, ничего не додумывать и помечать «(?)» места, где распознавание сомнительно. **Перед тем как пересылать выжимку, сверьте ключевые места по таймкодам с полным текстом**: вы отвечаете за то, что отправляете.

Как устроена выжимка, задаёт файл `app\summary_prompt.md`, его можно править. В первой строке выжимки указано, каким ИИ она сделана.

У локальной модели окно контекста обычно небольшое, и длинная расшифровка в него не помещается. Поэтому для неё текст обрабатывается частями примерно по 20 000 знаков: сначала по каждой части пишутся подробные заметки (задание в `app\summary_notes_prompt.md`), потом по заметкам делается выжимка. Размер части и окна можно задать в `app\ai.local.ini`, в разделе `[local]`: `chunk_chars`, `context`, `model`.

### Разделение по говорящим

Если включить разделение, абзацы выглядят так:

```
[00:01:10] Говорящий 1: Тема сегодня одна, запуск приложения...
[00:02:05] Говорящий 2: Да, мы опросили сто двадцать человек...
```

- **Имён инструмент сам не знает,** только номера, в порядке первого появления. Имена подставляет проверка текста ИИ (см. ниже); без неё ИИ называет людей по именам только в выжимке.
- **Как это работает:** отдельная модель (sherpa-onnx) по голосу размечает, кто говорит в каждый момент. Затем внутри длинных реплик голос проверяется заново каждые 0,75 секунды, чтобы короткие вставки другого человека («подожди, а сколько?») не оставались в чужом блоке. Это идёт на процессоре параллельно с распознаванием речи; вся обработка занимает примерно в полтора-два раза дольше, чем без разделения.
- **Насколько точно:** на открытых записях совещаний (корпус AMI, по 4 человека) при заданном числе говорящих верно приписаны 98 % слов и 89 % слов в коротких репликах до 2 секунд. Ошибки остаются в основном на коротких вставках и там, где говорят одновременно.
- **Число говорящих** — это сколько всего разных людей говорило за всю запись. Тот, кто подключился позже или вышел раньше, считается как обычно: запись разбирается целиком.
- **Кто сказал совсем мало** (меньше 2 % речи), при автоматическом подсчёте обычно приклеивается к самому похожему голосу. Если вы указали число говорящих, столько самых разговорчивых сохраняются отдельно, даже если кто-то из них сказал пару фраз. Поэтому, если знаете число, указывайте его.
- **Где ещё ошибается:** когда говорят одновременно, когда голоса очень похожи, при плохом звуке.

### Проверка текста ИИ

Разделение по голосам чаще всего ошибается на границах реплик: предложение разрезано между двумя говорящими, вопрос ведущего оказался внутри чужого ответа, короткий ответ получил метку спросившего. Проверка исправляет это по смыслу разговора и заодно подставляет имена:

```
было:  [01:45:00] Говорящий 1: Павел, а что
       [01:45:01] Говорящий 3: у тебя по срокам?
стало: [01:45:00] Марина: Павел, а что у тебя по срокам?
```

- **Имена** подставляются, если человек представился («меня зовут Марина») или к нему обратились по имени и он ответил. Если ИИ не уверен, будет «Марина (?)». Если ИИ дал одно имя двум разным говорящим, оно не подставляется никому.
- **Текст не переписывается.** ИИ не возвращает новый текст, только указывает: «эти слова из абзаца в 01:45:01 сказал такой-то». Инструмент сверяет каждую цитату с текстом дословно, а правку, которой в тексте нет, отбрасывает. Поэтому слова, их порядок и таймкоды остаются как были; меняются только метки, и разорванные предложения склеиваются.
- **Результат** в `<имя>.checked.txt`. В первой строке указано, каким ИИ сделана проверка, какие имена подставлены и сколько правок применено. Исходный `<имя>.txt` не меняется, по нему можно сверить спорные места.
- **Чего проверка не умеет:** исправлять ошибки распознавания слов и добавлять людей, которых разделение по голосам не нашло. Правит только то, что ясно из контекста; сомнительные места оставляет как есть.
- Проверка возможна, только если текст разделён по говорящим. Готовый `.txt` можно проверить и потом: `windows\transcribe.cmd <имя>.txt --check`.

### Перевод

Текст можно перевести на английский, немецкий или русский: на лету (вторая колонка в окне) или после встречи (вопрос «Перевести текст на другой язык?», галочка в окне или `--translate`).

- **Перевод локальный:** его делают модели Opus-MT Хельсинкского университета прямо на компьютере, текст никуда не уходит. Модель для пары языков скачивается при первом использовании, около 440 МБ (английский↔русский, английский↔немецкий). Немецкий↔русский идёт через английский: обе модели скачиваются, и перевод занимает вдвое дольше. Если на встречах нет интернета, скачайте всё заранее: `app\venv\Scripts\python.exe app\download_models.py --translation` из папки инструмента.
- **Скорость:** около трети секунды на предложение. На лету перевод появляется вместе с чистовым текстом, а 3 часа записи переводятся примерно за 15 минут (немецкий↔русский — за 30).
- **Качество:** смысл обычно передан, но модель небольшая и переводит каждое предложение отдельно, без контекста встречи. Поэтому бывают ошибки в терминах («релиз» → «освобождение»), датах и коротких фразах. Имена людей и продуктов могут исказиться.
- **Метки** переводятся тоже: «Говорящий 2» → «Speaker 2», «Вы» → «You». Имена, подставленные проверкой текста, остаются как есть.
- **Результат:** `<имя>.en.txt` (или `.de.txt`, `.ru.txt`) рядом с текстом, с теми же абзацами и таймкодами. На лету — `meeting.live.en.txt`.

**Проверка перевода ИИ.** Если отметить её, выбранный ИИ сравнивает каждый абзац оригинала с переводом и исправляет явные ошибки: смысл, пропуски, числа, даты, имена, термины. Как и при проверке текста, ИИ не переписывает перевод: он указывает слова и замену, а инструмент применяет только те правки, чьи слова дословно нашлись в этом абзаце перевода. Результат в `<имя>.en.checked.txt`; в первой строке сказано, сколько мест исправлено. Машинный перевод остаётся рядом без изменений. На тестовой встрече Claude исправил все 8 ошибок модели (например, «notes for graduation before 12:00» → «release notes by the 12th») и не тронул остальное.

Для проверки перевода ИИ получает и оригинал, и перевод, поэтому для неё действуют те же правила, что для выжимки (см. «Выжимка и правила использования ИИ»). Сам перевод без проверки текст никуда не отправляет.

### Повторный запуск

Готовые результаты не затираются, поэтому текст, который вы поправили руками, не пропадёт:

- если `<имя>.txt` уже есть, запись заново не расшифровывается. Если при этом нужна выжимка, а её ещё нет, она делается по имеющемуся тексту (удобно: сначала только текст, потом, если нужно, ещё раз перетащить и ответить «да» на вопрос о выжимке);
- если `<имя>.checked.txt` или `<имя>.summary.md` уже есть, проверка или выжимка заново не делается;
- чтобы переделать, добавьте `--force`. Только выжимку: `windows\transcribe.cmd <имя>.txt --summary --force`.

Если расшифровку прервать (закрыть окно, сбой), недописанный `.txt` не остаётся, и следующий запуск начнёт её заново.

### «Галлюцинации» Whisper

Whisper учился на субтитрах к видео, поэтому в паузах и шуме иногда «слышит» фразы, которых не было: «Продолжение следует...», «Субтитры сделал ...», «Спасибо за просмотр!». Бывает и зацикливание, когда одна фраза повторяется много раз подряд. Инструмент это убирает:

- короткие фрагменты с такими типовыми фразами выбрасываются. Обычная речь со словом «субтитры» остаётся;
- повтор внутри фрагмента («и так далее, и так далее, и так далее, и так далее») сворачивается до одного раза;
- фрагмент, который слово в слово повторяет предыдущий, выбрасывается. Короткие реплики вроде «Да.» не трогаются;
- каждое 30-секундное окно распознаётся без опоры на предыдущий текст, чтобы одна ошибка не тянулась дальше по записи.

В конце работы инструмент пишет, сколько всего убрано (строка `Filtered: ...`). Если кажется, что пропало нужное, перезапустите с `--no-filter` и сравните.

## Словарь терминов

Whisper часто искажает названия, фамилии и жаргон: «Джира» вместо Jira, «кубернетис» вместо Kubernetes, ошибки в фамилиях коллег. Словарь подсказывает модели, как эти слова пишутся правильно.

- **`terms.txt`** в папке инструмента, рядом с `README.md`: ваш постоянный словарь. Он **не попадает в git**, поэтому туда можно писать названия продуктов и проектов компании и фамилии коллег. Если файла нет, создайте его. Чтобы поделиться словарём с коллегами, отправьте им сам файл.
- **`--terms ФАЙЛ`**: словарь для конкретной встречи, например участники и темы. Параметр можно указать несколько раз.

Формат в обоих случаях один: один термин на строку, ровно в том написании, которое должно получиться. После `#` идёт комментарий.

```
Jira
Kubernetes
Иванов            # фамилии тоже можно
```

Правила:

- **Добавляйте только то, что реально распознаётся неправильно.** Модель может иногда вставить подсказанное слово туда, где его не произносили.
- **Держите список коротким.** Whisper читает не больше 223 токенов, это примерно 60–100 терминов. Остальное отбрасывается. При запуске инструмент показывает, сколько терминов и токенов использовано, и предупреждает, если список слишком длинный.
- **При переполнении первыми сохраняются термины из `--terms`**, потом из `terms.txt`.

## Выжимка и правила использования ИИ

Для проверки текста и для выжимки Claude и ChatGPT получают текст расшифровки под вашим аккаунтом. Поэтому для них действуют правила, под которыми вы пользуетесь этим ИИ: правила вашей организации, если это рабочий аккаунт, и условия использования Anthropic или OpenAI. Прежде чем отправлять текст, проверьте, что содержание встречи можно отправлять. Обычно нельзя отправлять:

- персональные данные сверх нужного, и **никогда** данные о здоровье и другие особые категории;
- пароли, ключи и другие учётные данные;
- конфиденциальные материалы клиентов и партнёров (цены, договоры, материалы под NDA), если правила или договор не разрешают их обработку в этом ИИ;
- частные и личные разговоры, если аккаунт рабочий. Для них делайте только локальный текст: на вопрос о выжимке ответьте «нет».

Локальная модель текст никуда не отправляет, но правила вашей организации о том, какие ИИ можно использовать, действуют и для неё.

Если сомневаетесь, не делайте выжимку: локальный текст получается и без неё. Если что-то недопустимое всё-таки ушло в ИИ, действуйте так, как требуют правила вашей организации.

| Linux, режим на лету: `Cannot use the sound system ... libpulse` | установите клиент PulseAudio: `sudo apt install libpulse0` (Ubuntu/Debian) |

## Linux

Работает так же, как в Windows: те же вопросы, то же окно расшифровки на лету, те же результаты. Проверено на Ubuntu 22.04 (в WSL, с видеокартой NVIDIA). Нужны `git`, `curl` и PulseAudio или PipeWire (они есть в обычном рабочем столе Ubuntu, Fedora и др.).

1. Скачайте инструмент, например в `~/transcribe`:
   ```
   git clone https://github.com/sbaranau/transcribe.git ~/transcribe
   ```
2. Запустите установку:
   ```
   bash ~/transcribe/linux/setup.sh
   ```
   Если `uv` нет, она спросит, поставить ли его с astral.sh в `~/.local/bin`. Ещё она спросит, добавить ли инструмент в меню приложений. Тогда там появятся «Расшифровать запись», «Расшифровка встречи на лету» и «Расшифровка: установка и обновление» (на языке интерфейса, см. «Язык интерфейса») с теми же значками, а «Расшифровать запись» появится и в «Открыть с помощью» у аудио и видео в файловом менеджере. Передумать: `linux/menu.sh add` или `linux/menu.sh remove`.
3. Пользоваться:
   - готовая запись: `~/transcribe/linux/drop-files-here.sh запись.mp4` (без файла спросит путь), или из меню, или «Открыть с помощью»;
   - на лету: `~/transcribe/linux/live-transcribe.sh` или из меню. Звук компьютера берётся с «монитора» устройства вывода PulseAudio/PipeWire. Результат в `~/Документы/Transcripts/` (или `~/Documents/Transcripts/`);
   - с параметрами: `~/transcribe/linux/transcribe.sh`, параметры те же, что в Windows.

Видеокарта NVIDIA используется, если установлен её драйвер; библиотеки CUDA ставятся вместе с пакетами. Если для режима на лету не хватает `libpulse`, установка об этом скажет (Ubuntu: `sudo apt install libpulse0`). Если `claude` или `codex` не нашлись сами, укажите путь к ним.

Одну и ту же папку не используйте из Windows и из Linux (например, через `/mnt/c` в WSL): окружения у них разные, установите отдельную копию.

## Состав папки

В самой папке только ярлыки и инструкции; скрипты для Windows и Linux лежат в своих папках, всё служебное в `app\`, туда заглядывать не нужно.

| Файл / папка | Что это |
|---|---|
| «Расшифровать запись», «Расшифровка встречи на лету», «Установка и обновление» | ярлыки со значками, их создаёт установка в Windows (не в git) |
| `windows\drop-files-here.cmd`, `windows\live-transcribe.cmd`, `windows\setup.cmd` | то, что запускают эти ярлыки |
| `windows\send-to-menu.cmd` | добавить или убрать пункт в меню «Отправить» |
| `windows\transcribe.cmd` | запуск из терминала с параметрами |
| `linux/` | то же для Linux: `setup.sh`, `drop-files-here.sh`, `live-transcribe.sh`, `transcribe.sh`, `menu.sh` (меню приложений) |
| `ИНСТРУКЦИЯ.md`, `README.md` | эта инструкция и краткое описание на английском |
| `docs\TECHNICAL.md`, `docs\THIRD_PARTY.md`, `docs\screenshots\` | подробное техническое описание (на английском), лицензии моделей и библиотек, скриншоты |

| `terms.txt` | ваш словарь терминов (необязательный, не в git) |
| `app\` | служебная папка: |

| `app\summary_prompt.md`, `app\summary_notes_prompt.md`, `app\check_prompt.md` | задания для ИИ: выжимка; заметки по частям длинного текста для локальной модели; проверка текста |
